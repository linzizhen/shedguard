# App 新手向交互重做（P21）设计规格

- 状态：已获用户批准（2026-11-12），实施中
- 触发：用户反馈「我能够打开，但是以我的角度来说，用起来挺复杂的」「你就把用户当做傻子。每一步都做详细一些」
- 设计依据：UI/UX Pro Max 技能（Claymorphism 风格与现有配色一致：#F97316 / #FFF7ED；触控目标 ≥44px；表单必须有可见标签；文案避免术语）

## 1. 目标与非目标

**目标**：一位没有技术背景的爬宠主人，从打开 App 到拿到第一次判定结果，全程不需要理解「服务器」「设备编号」「置信度」任何一个词。

**非目标**：不改服务端接口与算法；不做账号密码体系；不做真机推送（属 P18）。

## 2. 可用性验收标准（硬性）

1. 首屏（未建档）只有 1 个主按钮，且文字不含技术术语。
2. 完成「起名字 → 拍第一张」最多 3 次点击。
3. 结果页首屏只有：一句结论 + 一句建议 + 1 个主按钮；置信度/概率必须折叠。
4. 所有可点元素高度 ≥ 44px，正文字号 ≥ 15px。
5. 任何错误提示都必须是人话（例：「这张里没看清守宫，靠近一点、光线亮一点再拍一张」），不得出现英文错误码。
6. 底部导航 ≤ 3 个 Tab，且在 375px 宽度下不裁切。

## 3. 信息架构

```
欢迎向导（首次启动，3 步，可跳过）
  └─> 首页（拍照）  ← Tab1
        └─> 结果页（结论 / 建议 / 再拍 / 记下来）
  ├─ 蜕皮记录      ← Tab2
  │     └─> 提醒详情（照片 + 大白话）
  └─ 我的          ← Tab3
        ├─ 我的守宫（增删改）
        ├─ 提醒设置（设备编号 / 开启通知）
        ├─ 蜕皮知识
        ├─ 高级设置（服务器地址 / 重置身份）——默认折叠
        └─ 关于
```

原「知识」Tab 降级为「我的 → 蜕皮知识」入口，路由改为根级 `/knowledge`。

## 4. 逐屏规格

### 4.1 欢迎向导 `app/welcome.tsx`
- 步 1：大图标（paw）+ 标题「让小守宫的蜕皮不再错过」+ 说明「拍张照片，它就告诉你是不是要蜕皮了」+ 主按钮「开始」+ 次按钮「跳过」。
- 步 2：标题「先给你的守宫起个名字」+ 唯一输入框（可见标签「名字」，占位「比如：小橘子」）+ 品种可选 + 主按钮「保存，下一步」。名称空时按钮禁用并提示「给它起个名字吧」。
- 步 3：标题「准备好了」+ 说明「现在拍第一张照片试试」+ 主按钮「去拍第一张」（进首页并自动打开相机可后续实现，先回首页）+ 次按钮「稍后再说」。
- 完成时写 `shedguard.onboarded = "1"`；跳过也写，避免反复弹。

### 4.2 首页 `app/(tabs)/index.tsx`
- 标题「拍照查验」，副标题「拍一张它身上发白的地方」。
- 只有一个巨大圆形相机按钮（直径 ≥ 160px），按钮下小字「把手机对准它，尽量靠近、光线亮一点」。
- 辅助入口（小号文字按钮）：「从相册选一张」。
- 宠物选择：仅当宠物 ≥2 只时，在按钮上方显示一排小 chips「这是哪只？」；只有 1 只时不显示。
- 无宠物时（异常路径）：显示「先添加一只守宫」按钮。

### 4.3 结果页
- 载入中：「正在看照片…（大约 3 秒）」，带转圈，不白屏。
- 结论三态大字：
  - `shedding` → 「它正在蜕皮」+ 建议「接下来 2–3 天别帮它撕皮，把湿度调高一点」。
  - `normal` → 「看起来还没到蜕皮」+ 建议「过两三天再拍一张对比一下」。
  - `opaque` → 「它可能快蜕皮了」+ 建议「这几天多留意，湿度保持高一点」。
  - `unknown` → 「这张没看清」+ 建议「靠近一点、光线亮一点，再拍一张」。
- 主按钮「再拍一张」；次按钮「记到蜕皮记录」（点开预填今天的记录表单）。
- 「看看更多细节」折叠区：显示置信度百分比与三类概率条（给好奇的人，不影响主流程）。

### 4.4 蜕皮记录 `app/(tabs)/log.tsx`
- 顶部提醒卡：`「小橘子可能开始蜕皮了」+ 时间 + 「看看照片 ›」`；设备类提醒用「设备可能离线了」「最近没看到守宫」。
- 时间线：每行「11月12日 · 开始蜕皮」/「11月14日 · 已蜕完」。
- 主按钮「添加一条记录」，展开表单：开始日期（默认今天）、是否已蜕完（开关）、备注。
- 空状态：「还没有记录。守宫蜕皮时点这里记一条。」

### 4.5 我的 `app/(tabs)/settings.tsx`
- 「我的守宫」卡片：列表 + 「添加」。
- 「提醒」卡片：说明「设备会每 30 分钟拍一张，发现蜕皮就通知你」；「设备编号」输入 + 「保存并开启通知」；未打包时提示「已绑定，提醒会显示在蜕皮记录里」。
- 「蜕皮知识」入口 → `/knowledge`。
- 「高级设置」折叠：服务器地址（说明「只有自己搭服务器才需要改」）、重置身份。
- 「关于」：版本号 + 一句话说明。

## 5. 文案规范

- 禁用词：服务器、设备编号、置信度、概率、API、token、404/500、shedding_detected。
- 允许的替代表达：电脑上那个程序（服务器）、通知、这个设备。
- 一律用「它」称呼守宫；能具体到名字时用名字。

## 6. 技术实现要点

- `app/src/lib/onboarding.ts`：`ONBOARDED_KEY = 'shedguard.onboarded'`，`isOnboarded()/loadOnboarded()/markOnboarded()`。
- `app/src/app/_layout.tsx`：鉴权就绪后若 `!onboarded` → `router.replace('/welcome')`；注册 `welcome`、`knowledge`、`alert/[id]`、`pet/new`、`pet/[id]` 路由。
- Tab 由 4 改 3：`index`（首页）、`log`（蜕皮记录）、`settings`（我的，图标 person-outline）。
- 知识列表从 `(tabs)/knowledge.tsx` 移到根级 `app/knowledge.tsx`；原文件删除。
- 结果文案集中在 `app/src/lib/resultCopy.ts`：`resultHeadline(state)`、`resultAdvice(state)`、`resultKindLabel(kind)`，供首页与记录页复用。
- 不新增依赖；不改服务端。

## 7. 验收清单

1. 375 / 430 / 768 宽度截图逐屏检查，无横向溢出、Tab 不被裁。
2. 首屏、结果页、记录页、我的页均无禁用词（grep 校验）。
3. `npx.cmd tsc --noEmit`、`npx.cmd eslint .` 全绿。
4. 全流程手工走一遍：清空存储 → 向导 3 步 → 拍一张真图 → 结果 → 记一条 → 记录页可见。

## 8. 已知限制

- 向导在网页版刷新后若清空 localStorage 会重弹；属预期。
- 「记到蜕皮记录」只预填日期，仍需用户点保存（避免误写数据）。
- 多宠物场景仅做了 chips 选择，未做「按宠物分别看历史」的深化。
