# 蜕皮识别核心链路设计规格

- 状态：待批准
- 日期：2026-11-02
- 关联：`docs/data-survey.md`、`docs/roadmap.md`、`docs/specs/2026-11-02-server-image-ingest-design.md`

---

## 1. 目标

让系统能从「每天一张固定机位照片」里，回答两个问题：

1. 守宫在画面里的哪个位置？
2. 它现在的体表状态，相对过去一周的基线，是否出现了蜕皮前兆？

第一问用模型，第二问用可解释的信号与统计。两者都不依赖自有守宫数据已到手。

## 2. 非目标

- 不做端到端的「输入照片 → 输出蜕皮」黑箱模型。理由见第 3 节。
- 不做物种识别。第一版只服务干燥型地栖守宫，拍摄对象由用户保证。
- 不做实时视频推理。输入是每日静止帧。

## 3. 为什么拆成三层

公开数据集 `gecko_1` 的实测结构（详见 `docs/data-survey.md` 附录）：

| 事实 | 数值 |
|---|---|
| 图片总数 | 1,163 |
| `gecko` 实例 | 1,124 |
| `gecko-shedding` 实例 | 647 |
| 短边 < 400 px | 90.9% |
| 蜕皮组平均像素 | 451,295（约 670×670） |
| 无蜕皮组平均像素 | 69,863（约 300×230） |

分辨率与类别强耦合。若直接训三分类，模型会把「白背景 + 高清微距」当作蜕皮特征，而不是把「体表变白」当作特征。这是捷径学习，模型在真实场景必失效。

但把任务拆开后，第一部分变得可学：

- **「守宫在哪」不依赖蜕皮状态**。正视、侧视、绿叶遮挡、白底、暗光，都能标注出位置。跨物种、跨背景的 1,124 个实例，正好覆盖这种多样性。
- **「蜕皮前兆」不可学**。标注的是「大片白皮已经翘起」的瞬间快照，而我们要的信号是「提前 2–5 天，体表轻微发白、饱和度下降」。两者在视觉上差一个数量级，且样本光照是摄影棚白光，与红外夜拍毫无交集。

所以：模型只负责定位，剩下的交给信号与统计。

## 4. 定位层

### 4.1 训练数据构造

从 `gecko_1` 的 YOLO 分割标注转检测框：

- 只取类别 `gecko`（索引 0）。`gecko-shedding` 与 `gecko-abnormal` 不作为训练目标——它们是状态标签，不是物体标签。
- 多边形取外接矩形。
- 丢弃面积小于图片面积 1% 或边长小于 24 px 的框（太小，检测无意义，且会拉低定位精度）。
- 按原 `train/valid/test` 划分沿用，不重划。理由：原划分按图片来源分，同源图片已基本被拆散；重划收益低于成本。
- 记录每次训练的数据清单哈希，写进模型元数据的 `dataset_hash`，便于复现。

### 4.2 模型

- 架构：YOLOv8n 检测（`ultralytics`）。选择理由：单类别、小目标场景、需在后端 CPU 上跑；n 级别约 300 万参数，ONNX 导出后约 12 MB，CPU 单图推理在 100 ms 量级。
- 训练：`imgsz=640`、`epochs=60`、`batch=16`、`patience=15`，其余用 ultralytics 默认。
- 产出：`ml/artifacts/gecko-detector.pt` 与同名 `.onnx`。权重不进 Git（写入 `.gitignore`），只提交训练脚本与指标报告。

### 4.3 推理契约

```python
@dataclass(frozen=True, slots=True)
class Detection:
    box: tuple[int, int, int, int]      # x1, y1, x2, y2
    confidence: float                   # 0.0–1.0
    image_width: int
    image_height: int
```

- 接口 `Detector.detect(image_bytes: bytes) -> Detection | None`。
- 默认实现 `NullDetector`：返回整幅图作为框，`confidence=1.0`。用于无模型环境，保证链路可跑、测试不依赖权重文件。
- 正式实现 `OnnxDetector`：`onnxruntime` + 上述 `.onnx`。
- 多框时取面积最大者。理由：一只守宫一个饲养箱，画面里出现两个大框只可能是误检。
- 置信度低于 `SHEDGUARD_DETECT_MIN_CONFIDENCE`（默认 0.35）视为未检出。

## 5. 信号层

### 5.1 光照归一化

蜕皮前兆是「体表变白」，但相机自动曝光、昼夜色温漂移同样会让画面变白。两者必须分离，否则判定不可信。

做法：固定机位的优势在于背景不变。

- 取该设备最近 `SHEDGUARD_BACKGROUND_DAYS`（默认 7）天所有已分析图片的逐像素中位数，作为**背景参考**。
- 检测框之外、且在背景参考中稳定的像素（标准差低于阈值）构成**参考区**。
- 用参考区在当天的均值亮度，除以它在背景参考中的均值亮度，得到**曝光系数**。当天所有像素除以该系数，完成归一化。

这是整条链路里最关键的一步。没有它，后面所有指标都会被光照淹没。

若参考区像素不足（例如每天构图差异过大），跳过归一化并在指标里标 `normalized=false`，判定层对该帧降权而不是丢弃。

### 5.2 指标

在检测框内，收紧边缘 10% 后统计（避开框边缘的背景混入）：

| 指标 | 含义 | 蜕皮前的预期方向 |
|---|---|---|
| `lightness_mean` | CIELAB 的 L 通道均值 | 上升 |
| `lightness_std` | L 通道标准差 | 下降（表面变平整、发灰白） |
| `saturation_mean` | HSV 的 S 通道均值 | 下降（黄/橙褪成灰白） |
| `high_light_ratio` | L ≥ 80 的像素占比 | 上升 |
| `edge_density` | Canny 边缘像素占比 | 下降（皮纹模糊） |
| `color_entropy` | 色相直方图熵 | 下降（颜色趋同） |

选择 CIELAB 的 L 而不是 RGB 均值：L 更接近感知亮度，且与曝光近似线性，归一化后残差更小。

### 5.3 数据模型

表 `frame_metrics`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `image_id` | TEXT 主键，外键 images.id | 一图一行 |
| `box_json` | TEXT | `[x1,y1,x2,y2]` |
| `detector_confidence` | REAL | 检测置信度 |
| `detector_name` | TEXT | `null-detector` / `onnx:gecko-detector@<hash>` |
| `normalized` | INTEGER | 0/1，是否完成光照归一化 |
| `lightness_mean` | REAL | |
| `lightness_std` | REAL | |
| `saturation_mean` | REAL | |
| `high_light_ratio` | REAL | |
| `edge_density` | REAL | |
| `color_entropy` | REAL | |
| `computed_at_utc` | TEXT | |
| `metrics_version` | TEXT | 算法版本，规则改动时递增 |

`metrics_version` 是必需的。判定规则与指标口径会演进，没有版本号就无法解释历史告警为何与今天重算的结果不一致。

## 6. 时序判定层

### 6.1 基线

对每个指标，取该设备最近 `SHEDGUARD_BASELINE_DAYS`（默认 14）天、且 `normalized=true` 的帧，计算中位数 `M` 与 MAD。稳健 Z 分数：

```
z = 0.6745 * (x - M) / MAD
```

用中位数与 MAD 而不是均值与标准差：蜕皮当天的数据本身就是离群点，会污染基线。这是这类场景的标准做法。

MAD 为 0 时退化为：

```
z = (x - M) / max(std, 1e-6)
```

### 6.2 告警规则

方向按第 5.2 节的预期表：

- `lightness_mean`、`high_light_ratio` 上升为异常；
- `lightness_std`、`saturation_mean`、`edge_density`、`color_entropy` 下降为异常。

单个指标 `|z| ≥ SHEDGUARD_ALERT_Z_THRESHOLD`（默认 2.5）记为一票。连续 `SHEDGUARD_ALERT_CONSECUTIVE_DAYS`（默认 2）天，每天都有 ≥2 个指标越界，则产生一条 `pre_shed_signal`。

要求「连续 2 天 + 至少 2 个指标」而不是单日单指标，理由是单日噪声（相机噪点、守宫姿势不同、局部脱焦）足以造成假阳性。

### 6.3 回测

`shed_events` 表已有的事件记录是唯一真值。回测方式：

- 对每个事件日期 `D`，检查 `[D-14, D-1]` 内是否出现过 `pre_shed_signal`。
- 计算命中率与提前量分布。

当前没有真实事件记录，回测跑不起来。先用合成序列验证规则实现，等真实数据。

## 7. 接口

新增两个端点，均挂在 `/api/v1` 下：

- `POST /api/v1/analysis/{image_id}`：对单张图执行定位与信号提取，写入 `frame_metrics`，返回指标。重复调用幂等（同图同 `metrics_version` 直接返回已有结果）。
- `GET /api/v1/series/{device_id}/signals?from=&to=`：返回区间内每天的指标值与告警状态，供前端画趋势图。

`GET /api/v1/series` 保持原样不动。新端点用路径式 device_id，是因为它天然要求一个设备维度，与按区间查询的语义不同。

配置新增三项：`SHEDGUARD_DETECT_MIN_CONFIDENCE`（0.35）、`SHEDGUARD_BASELINE_DAYS`（14）、`SHEDGUARD_ALERT_Z_THRESHOLD`（2.5）、`SHEDGUARD_ALERT_CONSECUTIVE_DAYS`（2）。共四项，配置总数从 10 增至 14。

## 8. 验证策略

分三层，逐层加真实度：

1. **合成序列**（现在就能做）：构造 30 天的指标序列，注入「稳定 → 线性漂移 → 陡变」三种模式，断言判定层的输出符合预期。检验的是规则逻辑，不是视觉。
2. **公开数据抽查**（现在就能做）：拿 `gecko_1` 里若干张图跑定位层，人工看框准不准；对同一张图的多次增强（亮度 ±10%、饱和度 −15%）跑信号层，断言指标变化方向正确。检验的是实现正确性。
3. **真实序列回测**（需真实数据）：见 6.3。

第 2 层的亮度/饱和度扰动测试是防线：如果连「人为把图调亮 10%」都无法让 `lightness_mean` 单调上升，说明归一化或指标实现有 bug，必须修好再谈判定。

## 9. 分期与验收

| 阶段 | 交付 | 验收 |
|---|---|---|
| M4 | 数据转换脚本、训练脚本、检测器训出并评估 | `mAP50 ≥ 0.85`（单类别、场景简单，低于此值说明数据转换有错）；`ml/artifacts/` 有指标报告 |
| M5 | `Detector` 抽象 + `NullDetector` + `OnnxDetector`、信号层、`frame_metrics` 表与迁移 | 扰动测试全绿；同一张图重复分析幂等；无模型时链路可用 |
| M6 | 判定层、告警规则、`signals` 端点、合成序列测试 | 合成序列三种模式的判定结果符合预期；覆盖率总体 ≥ 85% |

M4 与 M5 可并行：M5 用 `NullDetector` 开发，不阻塞。

## 10. 已知欠账

- 定位模型在红外夜拍图上的表现未知。训练数据全是可见光。**这是整条链路最大的未知**，需真实红外图到手后重新评估，很可能要用手工标注的几十张真实图做微调。
- 光照归一化依赖「背景稳定」，若饲养箱位置被移动则失效。当前无检测机制。
- 指标阈值是经验值，未经真实数据校准。
- 不处理守宫未入镜、大面积脱焦、部分遮挡的情况。
- 蜕皮「进行中」与「即将蜕皮」共用同一套信号，未做区分。

## 11. 实现记录（M5）

信号层已按本文第 5、7 节落地，但有三处与规格原文不同，均为「先跑通、再精化」的主动取舍：

| 规格原文 | 实际实现 | 理由与代价 |
|---|---|---|
| 5.1：逐像素中位数构建背景参考图，再按「标准差低于阈值」选出参考区，逐像素归一化 | 只取**框外像素 L 的中位数**作为标量背景亮度，用「当天背景 ÷ 近 N 天背景中位数」得到 `exposure_scale`，对整图做统一除法 | 逐像素参考图要求每天构图完全一致，真实机位会有轻微位移，逐像素相减会引入比信号更大的噪声。标量版本少一个「参考区掩膜」的自由度，代价是对局部光照变化（例如一半画面被反光覆盖）不敏感。`background_lightness` 字段已落库，后续要做逐像素版本时可直接复用 |
| 5.1：参考区像素不足时标 `normalized=false` | `normalized` 表示「有没有可用的历史背景」：当天是该设备第一次被分析时为 `false`，之后为 `true` | 标量版本不存在「参考区不足」这个失败态，但保留同一个字段名与语义方向，消费方代码不用改 |
| 5.3：`detector_name` 形如 `onnx:gecko-detector@<hash>` | `onnx:<模型文件名主干>`，例如 `onnx:gecko-det` | 模型文件按名字版本化（`ml/models/gecko-det.onnx`），hash 已体现在文件名里，不再重复计算 |

另外两处补充约定：

- `SHEDGUARD_DETECTOR_MODEL` 为空时装配 `NullDetector`，把整张图当作身体。这条路径保证「没有模型也能上传、分析、看到指标」，用于联调和演示，真实判断必须配模型。
- 指标版本常量 `METRICS_VERSION = "1"` 与 `detector_name` 一起构成幂等键：同一张图用同一版本、同一检测器重复分析直接返回旧记录；换模型或改算法要递增版本号，否则旧结果会被当成新结果。
