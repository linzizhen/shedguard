# 蜕皮时序判定层设计（M6）

- 状态：草案
- 日期：2026-11-02
- 作者：linzizhen
- 上游规格：`docs/specs/2026-11-02-shed-detection-core-design.md`

## 一、目的与范围

M5 把每一帧变成六项体表指标，但指标本身不会说话。亮度均值从 45 涨到 52，可能是蜕皮前兆，也可能是换了根更亮的灯管。这一层要回答的问题是：

> 这只守宫，今天是不是正在进入蜕皮期？

范围限于单设备、单个体、干燥型地栖守宫。不处理多只混养、不处理湿度型蜕皮（睫角守宫那种）。

### 非目标

- 不做蜕皮开始日与结束日的精确切分
- 不做个体识别（假设一台设备长期只拍一只）
- 不解释原因（温度、湿度、喂食都不在本层输入内）

## 二、输入与输出

### 输入

某个 `device_id` 在区间内的每日指标序列，来自 M5 的 `frame_metrics` 表：

- `local_date`、`image_id`
- 六项指标：`lightness_mean`、`lightness_std`、`saturation_mean`、`high_light_ratio`、`edge_density`、`color_entropy`
- `detected` 标志（未检出的日子六项指标为空）

### 输出

每天一条判定记录：

| 字段 | 含义 |
| --- | --- |
| `date` | 当地日期 |
| `image_id` | 当天代表帧，缺失为 `null` |
| `metrics` | 六项指标原值，缺失为 `null` |
| `z_scores` | 六项稳健 Z 分数，缺失为 `null` |
| `hits` | 命中的指标名列表（方向正确且越界） |
| `state` | `insufficient` / `normal` / `watch` / `alert` |
| `baseline_samples` | 当天基线用了多少个样本 |

## 三、算法

### 3.1 稳健基线

对每一天 `d`，取 `[d - SHEDGUARD_BASELINE_DAYS, d)` 区间内**所有可用样本**作为基线，不含当天。**不得使用当天及之后的数据**，否则判定会用到未来信息。

对每项指标独立计算：

```
median = 中位数(samples)
mad    = 中位数(|samples - median|)
z      = 0.6745 * (x - median) / mad
```

`0.6745` 是正态分布下 MAD 与标准差的换算系数，使得 `|z| >= 2` 大致对应「偏离中心两个标准差」，便于直觉理解。

**为什么不用标准差**：蜕皮当天本身就是离群点，用 `[d-N, d]` 窗口算标准差会被它自己撑大，越接近蜕皮越难检出。MAD 的崩溃点是 50%，只要一半以上样本是正常的就不受影响。

### 3.2 尺度为零的退化处理

`mad == 0` 意味着基线样本有一半以上完全相同（合成图、静止画面、故障相机都可能出现）。此时：

1. 退化为平均绝对偏差：`scale = mean(|samples - median|)`
2. 若 `scale` 仍为 0（全部样本同值），则该指标当天判为 `z = 0`，不参与命中
3. 尺度下限兜底：`scale = max(scale, 1e-6)`，避免除零

### 3.3 方向性判定

蜕皮前兆有明确方向：皮肤发白、失水起皱、色素褪去。因此只认「符合先验方向」的越界，反向偏离不算命中。

| 指标 | 方向 | 依据 |
| --- | --- | --- |
| `lightness_mean` | 升高 | 旧皮与皮肤分离后充满空气，散射增强，视觉上发白 |
| `lightness_std` | 升高 | 蜕皮从局部开始，白斑与正常皮肤并存，画面亮度分布变宽 |
| `saturation_mean` | 降低 | 色素层随旧皮脱落前被稀释，颜色趋灰 |
| `high_light_ratio` | 升高 | 皮屑翘起的反光面增多 |
| `edge_density` | 升高 | 旧皮起皱，纹理边缘变密 |
| `color_entropy` | 降低 | 颜色向白色收敛，色相分布变窄 |

**只认方向不认幅度**的好处：灯管变暗、镜头脏污这些「整体变暗」的异常不会触发告警。

**代价**：若某只守宫的蜕皮表现为「变暗」（比如深色品系），这套规则会漏报。规格承认这一点，把方向表做成可配置的常量，等真实数据积累后再校准。

### 3.4 命中与状态

```
hits = [指标 for 指标 if 方向正确 and |z| >= SHEDGUARD_ROBUST_Z_THRESHOLD]
```

状态判定：

| 状态 | 条件 |
| --- | --- |
| `insufficient` | 基线可用样本数 `< SHEDGUARD_MIN_BASELINE_SAMPLES` |
| `alert` | 连续 `SHEDGUARD_ALERT_CONSECUTIVE_DAYS` 天，每天 `len(hits) >= SHEDGUARD_ALERT_MIN_SIGNALS` |
| `watch` | 当天 `len(hits) >= SHEDGUARD_ALERT_MIN_SIGNALS`，但未满足连续条件 |
| `normal` | 其余情况 |

**为什么要求连续两天**：单日跳变在真实场景里太常见——换水盆、开门透光、守宫刚好面壁。要求连续，是把「瞬时干扰」和「持续变化」分开的最便宜手段。

### 3.5 缺失处理

- 当天无代表帧（`image_id` 为 `null`）：状态记 `insufficient`，`hits` 为空，**连续性计数清零**。没有证据的日子不能累积，也不能当作正常日继续累加。
- 当天未检出守宫（`detected == false`）：同上，指标为空，不参与判定，连续性清零。
- 基线窗口内的缺失日直接跳过，不补零、不插值。

**为什么是 `insufficient` 而不是 `normal`**：一张图都没有的设备如果返回 `normal`，消费方会显示「一切正常」的绿灯，而事实是「什么都判断不了」。把「无法判断」单独标出来，前端才能诚实地显示「还没有数据」。

## 四、接口契约

### `GET /api/v1/series/{device_id}/signals`

查询参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `from` | `YYYY-MM-DD` | 是 | 区间起始 |
| `to` | `YYYY-MM-DD` | 是 | 区间结束，不得早于 `from` |

约束沿用 M3：区间不得为空、不得颠倒、跨度不超过 366 天。

响应：

```json
{
  "device_id": "cam-living-room",
  "from": "2026-11-01",
  "to": "2026-11-05",
  "days": [
    {
      "date": "2026-11-01",
      "image_id": "01J9...",
      "metrics": { "lightness_mean": 45.2, "...": 0.0 },
      "z_scores": { "lightness_mean": 0.41, "...": 0.0 },
      "hits": [],
      "state": "normal",
      "baseline_samples": 12
    }
  ],
  "alert_days": 0,
  "current_state": "normal"
}
```

- `alert_days`：区间内处于 `alert` 的天数
- `current_state`：区间最后一天的状态

### 为什么实时计算而不落表

判定结果完全由 `frame_metrics` 决定，落表会引入「指标更新了但判定没更新」的一致性问题。单个设备一年的数据量不过几百行，实时算的开销可以忽略。等将来需要推送通知时，再用定时任务把结果算出来存下来。

## 五、配置

在现有 13 项基础上新增五项，共 18 项：

| 变量 | 默认值 | 范围 | 含义 |
| --- | --- | --- | --- |
| `SHEDGUARD_BASELINE_DAYS` | 14 | 3–90 | 基线回看天数 |
| `SHEDGUARD_MIN_BASELINE_SAMPLES` | 7 | 3–90 | 判定所需最少样本数 |
| `SHEDGUARD_ROBUST_Z_THRESHOLD` | 2.0 | 1.0–6.0 | 单指标越界阈值 |
| `SHEDGUARD_ALERT_MIN_SIGNALS` | 2 | 1–6 | 触发所需的最少命中指标数 |
| `SHEDGUARD_ALERT_CONSECUTIVE_DAYS` | 2 | 1–7 | 触发所需的连续天数 |

`MIN_BASELINE_SAMPLES` 与 `BASELINE_DAYS` 分开配置，是为了让样本稀疏时能独立调低门槛而不必缩短回看窗口。

## 六、验收标准

1. 基线只使用当天之前的数据，未来数据不参与
2. 合成序列：前 14 天平稳，第 15–16 天亮度与高光同步上升，第 16 天返回 `alert`
3. 同样的序列，若只有第 15 天越界，第 16 天恢复平稳，返回 `watch` 而非 `alert`
4. 方向性：亮度**下降**同样幅度不产生命中
5. 缺失日中断连续性：第 15 天越界、第 16 天无图、第 17 天越界，第 17 天为 `watch`
6. 样本不足 7 天返回 `insufficient`
7. 全部样本同值时 `mad` 退化，不抛除零异常
8. 未检出守宫的日期指标为空，状态为 `insufficient`
9. 区间跨 366 天以上返回 400 `INVALID_REQUEST`
10. 覆盖率门槛保持总体 85%、`domain/` 与 `services/` 90%

## 七、已知欠账

1. **方向表未经真实数据校准**——六项指标的方向来自蜕皮生理常识，不是从数据里学出来的。真实数据到手后必须重新核对。
2. **阈值是拍的**——`z >= 2`、连续 2 天、至少 2 个指标，这三个数字都没有数据支撑。
3. **不做个体自适应**——同一只守宫不同阶段的基线会漂移（幼体生长、成体体重变化），当前用固定回看窗口近似。
4. **不区分开始与结束**——蜕皮完成后指标会反向回落，同样可能触发告警，当前不做抑制。
5. **不看环境上下文**——温度、湿度、喂食记录都不在输入内，这些因素会独立影响体色。
6. **无通知推送**——判定结果只通过接口暴露，主动提醒属于 Phase 7。
