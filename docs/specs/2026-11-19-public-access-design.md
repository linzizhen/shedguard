# 公网可达的一体化服务（A 包）设计

> 状态：待批准
> 创建：2026-11-19
> 关联：`docs/plan.md` §4 主线；本设计对应「让软件能被打开」这一段路，暂不登记 P 编号，批准后补登记。

## 1. 背景

到 2026-11-19，软件功能已经齐了：收图、判定、提醒、萌照、摄像头接入、数据贡献，服务端 523 个测试全绿。但这些能力**只在一个前提成立时可用**：服务端跑在开发者本机、仅监听 `127.0.0.1`、手机必须和电脑同一个局域网、并在 App 的「高级设置」里手填内网 IP。

也就是说，除了开发者本人、且必须坐在电脑旁边，没有人能用上这套东西。

## 2. 目标与非目标

**目标**：让人把「一个网址」发给任何人，对方用自己的手机（移动网络、非同一局域网）打开，就能完整走完「打开 → 拍照/选图 → 得到结论 → 在日志里看到记录」，全程不需要填写任何地址。

**非目标（本设计不做）**：

- 不做注册、密码、找回密码、第三方登录；
- 不做自有域名与固定隧道（Named Tunnel 需要域名，另议）；
- 不做证书管理（隧道已提供 https）；
- 不做多实例、负载均衡、容器编排；
- 不改任何判定算法与数据模型。

## 3. 范围

| 编号 | 事项 | 说明 |
| --- | --- | --- |
| A1 | 服务端托管前端构建产物 | 同一个 URL 既是 App 也是 API，不再需要同时开两个进程 |
| A2 | App 自动推断服务地址 | 页面就是服务本身时，地址取当前页面来源，不再手填 |
| A3 | 前端构建入口 | 一个命令产出 `app/dist`，供 A1 托管 |
| A4 | 隧道启动脚本 | 一个命令把本机服务变成 `https://<随机>.trycloudflare.com` |
| A5 | 一键启动脚本 | 串起「构建 → 起服务 → 起隧道 → 打印网址」 |
| A6 | 演示手册 | `docs/public-demo.md`：怎么开、怎么关、链接为什么会长变、暴露期间注意什么 |

## 4. A1：服务端托管前端

### 4.1 配置

新增一项 `web_dir: str = ""`（`SHEDGUARD_WEB_DIR`）。

- 显式给路径：用该目录；
- 留空（默认）：探测仓库内的 `app/dist`（按 `server/src/shedguard_server/config.py` 的位置向上三级得到仓库根，再拼 `app/dist`）；
- 目录不存在：**不挂载**，启动日志打一条 warning（「未找到前端构建产物，跳过页面托管」），服务端行为与现在完全一致。

### 4.2 路由优先级

挂在所有 API 路由**之后**注册一个兜底路由 `GET /{path:path}`：

1. 以 `api/` 开头的路径 → 交给既有路由，未命中即 404，兜底路由不接管；
2. `healthz`、`readyz`、`docs`、`openapi.json` 同样不接管；
3. 请求路径能在 `web_dir` 里找到真实文件 → 直接返回该文件；
4. 其余 → 返回 `index.html`（前端是单页应用，`/log`、`/portrait/xxx` 这类客户端路由靠它接管）。

### 4.3 缓存头

- `assets/` 下的文件名带内容哈希 → `Cache-Control: public, max-age=31536000, immutable`；
- `index.html` → `Cache-Control: no-cache`，避免发版后手机还拿旧页面。

## 5. A2：地址自动推断

现状：`app/src/lib/serverUrl.ts` 的默认值是 `EXPO_PUBLIC_SERVER_URL ?? ""`，为空时要求用户在「高级设置」里手填。

改法（保持向后兼容）：

1. 显式设置了 `EXPO_PUBLIC_SERVER_URL` → 用它（本地开发与真机包的行为不变）；
2. 否则在 Web 端：取 `window.location.origin`，但**排除**开发服务器端口（`8081`、`19006` 等 Metro/Expo 端口），避免开发时把 API 指到自己；
3. 原生端仍为空，由用户填写（B 包把这一步换成扫码）。

判定逻辑放在 `serverUrl.ts` 的纯函数里，便于单测。

## 6. A3：前端构建

`app/package.json` 增加脚本：

- `build:web`: `expo export --platform web`（产物在 `app/dist`，该目录加入 `.gitignore`）。

`app.json` 的 `web` 段确认使用单页输出（`expo-router` 默认 `output: "single"`），与 A1 的兜底路由相匹配；如实际产物是静态多页，则兜底路由改为按路径映射真实文件、失败再回 `index.html`（同一套逻辑已覆盖）。

## 7. A4/A5：隧道与一键启动

### 7.1 隧道

用 Cloudflare 免费快速隧道：不需要账号、不需要域名，一条命令换一个 https 网址。

`scripts/tunnel.ps1`：

1. 检查 `.tmp/cloudflared.exe`；不存在则用项目 venv 的 Python 从官方 release 下载（PowerShell 的 `Invoke-WebRequest` 在本机因 schannel 证书问题不可用，实测 Python `urllib` 可以），下载失败给出「手动下载放到 `.tmp/`」的提示；
2. 启动 `cloudflared tunnel --url http://127.0.0.1:<port> --no-autoupdate`，日志写 `.tmp/tunnel.log`；
3. 轮询日志抓 `https://[a-z0-9-]+\.trycloudflare\.com`，抓到就打印网址与「把这个网址发到手机上」；
4. 超时（默认 60 秒）没抓到就打印日志尾部并退出，不留孤儿进程；
5. 收到 Ctrl+C 时结束子进程。

### 7.2 一键启动

`scripts/serve-public.ps1`：

1. 若 `app/dist` 不存在（或传 `-Rebuild`）→ 先跑 `build:web`；
2. 后台起服务端（`PYTHONPATH=server/src`，`SHEDGUARD_RATE_LIMIT_PER_MINUTE=60`，端口默认 8010，可 `-Port` 覆盖）；
3. 等服务端 `/healthz` 返回 ok；
4. 起隧道并打印网址；
5. Ctrl+C 时同时停掉隧道与服务端。

### 7.3 为什么不改全局默认值

`rate_limit_per_minute` 的默认值保持 `0`（关闭），只在演示启动脚本里显式设成 60。理由：默认值一改，既有 523 个测试里所有「未配置限流」的用例都会受影响，而公网暴露只是特定场景。**行为差异由脚本承担，不污染默认配置。**

## 8. 安全与风险

公网暴露改变了威胁模型，必须写清楚：

| 风险 | 现状 | 缓解 |
| --- | --- | --- |
| 拿到链接的人都能建匿名账号、上传图片 | 匿名令牌即身份，没有任何门禁 | 演示期间使用、用完即关；开启限流 60 次/分；单图上限 10 MB |
| 链接是公开可猜的随机串 | 不公开索引，但被转发即扩散 | 明确告知「这个链接等于家门钥匙，别公开发」 |
| 照片明文存储、无 HTTPS 终结 | 隧道已提供 https，但落盘仍是明文 | 本设计不处理；列在既有欠账里 |
| 电脑关机即断、链接重启即变 | 免费隧道特性 | 手册里写明；要长期在线则迁云服务器（同一套服务端，无需改代码） |

## 9. 验收标准

1. **真机链路**：手机用移动网络（关闭 Wi-Fi）打开隧道网址 → 首页正常 → 选一张图 → 得到结论 → 日志页能看到这条记录与提醒横幅，**全程没有填写过任何地址**。
2. **API 不被吞**：`/api/v1/pets`、`/healthz`、`/docs` 在托管静态文件后行为不变；未知 API 路径仍是 JSON 404 而不是 index.html。
3. **未构建时不挂载**：删掉 `app/dist` 起服务，`/api/v1/pets` 正常、`/` 返回 404，日志有 warning。
4. **质量门**：`pytest` 全绿（现有 523 + 新增托管用例）、覆盖率不低于 85%、`ruff check .`、`mypy src tests` 全绿；App 侧 `tsc --noEmit` 与 `eslint` 全绿。
5. **脚本可重复**：连续跑两次 `serve-public.ps1` 都能起来；中断后端口与子进程被清理。

## 10. 实施顺序

1. A1 服务端托管 + 单元/集成测试（含优先级与缓存头）；
2. A3 构建脚本 + `app/dist` 的 `.gitignore`；
3. A2 地址推断纯函数 + 测试；
4. A4/A5 两个脚本；
5. A6 手册；
6. 真机验收（手机流量）；
7. 收尾：`docs/plan.md` 登记该里程碑（P33）、`docs/handoff.md` 同步。
