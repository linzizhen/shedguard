# 项目总计划（唯一权威）

> 本文件是本项目**唯一的计划来源**。任何开发都必须先与本文件的「当前主线」对齐。
> 角色分工：本文件 = 计划与优先级；`docs/specs/` = 具体设计；`docs/handoff.md` = 状态快照；`docs/roadmap.md` = **早期规划存档（已过期，不得作为开发依据）**。

---

## 0. 使用规则（最重要，先读这一节）

### 0.1 铁律

1. **计划先行**：先有计划，再有规格，最后才是代码。顺序不可颠倒。
2. **新方案 = 先重排计划**：出现新方案、新需求、新数据结论时，**第一步是改本文件**（登记变更 + 重排里程碑 + 更新当前主线），然后才允许写规格、写代码。
3. **禁止按旧计划开发**：不允许拿着过期的计划或过期的规格直接开工。发现计划与现实不符，先停下来改计划。
4. **一次只推进一个主线**：同时最多一个「进行中」的主线；其余是「待办」或「待定」。

### 0.2 新方案的标准处理流程（强制）

| 步骤 | 动作 | 产出 | 谁能做 |
|---|---|---|---|
| 1 | 在 §6 变更记录登记一行：日期 / 变更内容 / 影响哪些计划项 | 一行记录 | 我 |
| 2 | 重排 §3 里程碑、§4 当前主线，标出新增/取消/降级 | 更新后的计划 | 我 |
| 3 | 影响架构 / 接口 / 数据模型的，写或改 `docs/specs/` 里的规格，**等用户批准** | 规格文档 | 我 → 用户批准 |
| 4 | 计划与规格都定稿后，才开始写代码 | 代码 + 测试 | 我 |
| 5 | 提交前自检：本次代码是否只做「当前主线」里的事 | 提交 | 我 |

> 一句话：**没改计划，不许改代码**。哪怕是很小的新增方案，也要在 §6 留一行。

### 0.3 冲突时的优先级

用户当次指令 > 本文件 > 规格文档 > `docs/roadmap.md`（存档）。
若用户指令与本文件冲突，先执行用户指令，**并在同一轮内更新本文件**，避免计划再次过期。

## 1. 项目现状（一句话）

shedguard 是一个爬宠蜕皮监测系统：饲养箱摄像头定时抓拍 → 服务端判定守宫是否「正在蜕皮」→ 通过 App 推送提醒主人查看。**软件（服务端 + 模型 + App + 固件代码）已全部完成并通过本地验证；尚未上真机、没有真实饲养箱数据。**（详细状态见 `docs/handoff.md`）

当前最新提交：`d03e04c`（2026-11-12），仓库与 origin/main 同步。

---

## 2. 产品范围与硬边界（当前版）

### 2.1 做

- **蜕皮检测**：判定当前这一帧是「正常 / 正在蜕皮」，在状态发生跃迁（正常 → 正在蜕皮）时提醒。
- **定时抓拍 + 服务端判定**：设备每 30 分钟抓一张（仅白天 08:00–20:00），上传后服务端自动分析。
- **App**：宠物档案、手动蜕皮日志、拍照查验、知识库、卡皮风险评估、蜕皮提醒列表与推送。
- **二期（待数据）**：蒙白期识别（三态分类），需要 ≥150 张蒙白样本。

### 2.2 不做

| 不做 | 原因 |
|---|---|
| **蜕皮日期预测 / 提前预警** | 2026-11-11 用户决策下线：没有足够个体历史，预测不可靠。接口保留但标 Deprecated，不再开发 |
| 自动喂食 / 自动控温控湿 / 整箱产品 | 非差异化或成本结构不成立 |
| 健康诊断 | 只做观察提示，不替代异宠医生 |
| 一开始覆盖所有爬宠 | 只做干燥型地栖守宫（豹纹、肥尾） |
| 端侧推理（板子上跑模型） | 2026-11-11 决策：服务端推理，板子只负责拍照上传 |
| 夜间 / 红外抓拍 | 无红外训练数据，接受「只在白天拍」 |

> 注：早期边界里写「单张照片识别蜕皮不可靠，不做」。**现改为**：单帧状态识别可以做，但它是「定时序列里的一帧」，不承诺「单张即结论」；判定仍要结合前后日状态与置信度阈值。

## 4. 当前主线与下一步

**当前主线：P11 固件上板联调（阻塞于硬件）。**

在没有硬件之前，不新开功能分支，只做不依赖硬件的收尾工作（按优先级）：

1. **P11 固件上板联调** —— 需要 ESP32-S3-EYE 实物。（主线，阻塞）
2. **P12 真实数据采集** —— 需要饲养箱与守宫。（主线，阻塞）
3. 无硬件时的可选项（不改变计划主线）：
   - 数据集扩充与复核（把 `data/collected` 里错物种的图清出去，补更多 shedding 样本）
   - App 细节打磨（空态、错误提示、无障碍）
   - 文档与规格同步

**下一个要做决定的分叉点**：拿到硬件后，先做 P11 联调；联调通过后，P12 采集 1–2 周真实数据，再回来看是否具备 P13（蒙白）与 P14（个体校准）的启动条件。
