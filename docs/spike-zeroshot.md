# 探路：现成的通用视觉模型能不能直接用（CLIP 零样本 / few-shot）

> 日期：2026-11-12
> 目的：回答「网上有没有别人做好的模型能拿来用」，并判断在当前架构（服务端推理）下是否需要继续自采数据。

## 1. 先查了一圈，结论是没有现成的

| 来源 | 找到什么 | 能不能用 |
|---|---|---|
| HuggingFace `emaeon/vit-...-finetuned-gecko` | 守宫图像分类小模型，13 次下载、无模型卡、无评测 | 不能，最多当特征参考 |
| HuggingFace `Straueri/ReptileAmphibianClassification`、`richardb/Reptiles` | 爬行/两栖类**物种**分类 | 不能，与蜕皮无关 |
| Roboflow `GECKO`、`Reptile` 数据集 | 公开检测集 | 能，可补充检测器数据（我们已在用其中一个） |
| LooksLikeCode「爬宠蜕皮进度识别」技能 | 商业 API + 提示词封装，不是可下载模型；黑盒、需额度、图片出境 | 不建议作为技术底座 |
| 通用基础模型（CLIP / SigLIP / SAM2 / YOLO-World / 小 VLM） | 通用能力，非本任务 | 值得实测，见下 |

没有任何公开模型是「守宫蜕皮状态」专用。所以要验证的是：**通用语义模型零样本能做到什么程度。**

## 2. 实测一：CLIP 零样本

脚本 `ml/eval_zeroshot.py`，模型 `openai/clip-vit-base-patch32`，数据集 `ml/datasets/gecko-state-v2`。
每个类别用多条中英文提示词取平均文本向量，与图像向量做余弦相似度后 softmax。

| 切分 | 样本 | AUC | 0.5 阈值准确率 | 最优阈值 | 最优准确率 | 最优召回 |
|---|---|---|---|---|---|---|
| test | 112（32 正） | 0.7918 | 0.4286 | 0.952 | 0.8036 | 0.4062 |
| valid | 349（91 正） | 0.7758 | 0.3782 | 0.953 | 0.7966 | 0.4066 |

**读法**：AUC 约 0.78，说明「正常皮 vs 白皮」在语义空间里**确实有一定可分性**（远高于随机 0.5）；
但分数严重压缩、校准极差——在 0.5 阈值下把几乎所有图都判成 shedding（召 0.96、精 0.33）；
即使挑最优阈值，召回也只有 0.41。**结论：零样本不能直接用于产品判定。**

## 3. 实测二：CLIP 特征 + 少量标注（few-shot 原型分类器）

脚本 `ml/eval_fewshot.py`。用 CLIP 图像特征，每类只抽 k 张做原型（类别均值），余弦相似度分类，重复 5 次取均值。

| 每类标注张数 | 准确率（均值） | 准确率（最好一次） | 蜕皮召回 |
|---|---|---|---|
| 1 | 0.6679 | 0.7589 | 0.5625 |
| 5 | 0.7607 | 0.8482 | 0.7562 |
| 10 | 0.8071 | 0.8661 | 0.8063 |
| 20 | **0.8339** | **0.8839** | **0.90** |

对照：全量微调的 ResNet18（用 747 张训练图）测试集准确率 **0.9286**、蜕皮召回 **0.8125**。

**关键发现**：每类只要 20 张标注（合计 40 张），就能到 0.83 准确率，且**蜕皮召回 0.90 反而高于全量微调模型**。
这说明这个任务的特征非常「浅」——白皮的颜色/质感差异足够显著，不需要成千上万张图。

## 4. 结论与建议

1. **不要买/接第三方 API**：没有现成专用模型，商业 API 是黑盒且无法离线。
2. **零样本直接上线不可行**（召回 0.41），但**特征迁移非常有效**。
3. **采数据的策略可以大改**：不必追求每类几百张。按实测，真实机位下每类 **30–50 张**（覆盖不同个体/光照）就足以训出可用模型；这也解释了为什么现在 747 张能到 0.93——数据量早已过剩，瓶颈在「同分布」而非「数量」。
4. **上板另算**：CLIP ViT-B/32 约 600 MB，板上不可能。若将来要做端侧，走 MobileNetV3-Small int8（约 2–3 MB）+ 蒸馏，训练脚本已支持该架构。
5. **下一步可做**：把「标注 40 张 → 训原型分类器」做成产品里的「个体校准」流程，用户买回去拍十几张就能用，不必等我们攒大数据集。

## 6. 已知限制

- 测试集与训练集同源（Roboflow 网图），域偏移问题依然存在；本结论只说明「特征可分性」，不代表真实机位准确率。
- few-shot 只在「与测试集同分布」的 train 里抽样，真实场景应先用自己的 20–40 张标定。
- 只测了 CLIP ViT-B/32；SigLIP / ViT-L 可能更强，未测。

## 7. 个体校准的数据从哪来（后续方向，用户提议）

用户不认可「让用户专门拍 30–50 张」的交互（负担太重）。他的想法：**饲养箱里的摄像头本来就在按 30 分钟定时抓拍，这些图天然可以充当个体校准样本**——同一只守宫、同一机位、同一光照，积累几天就有几十张；用户不需要额外做什么，只在想补拍时再补几张。

这条路径的好处：

- 零额外采集成本：校准样本来自已经在跑的业务链路，不需要新的拍摄流程。
- 分布天然对齐：同一机位、同一光照、同一个体，正是 few-shot 原型法最需要的「同分布」样本。
- 数据越多越准：可以用「已上传的历史图 + 人工确认过的蜕皮记录」做半监督式的原型更新，逐步逼近全量微调的准确率。

待验证的问题：先要做真机数据，确认「同一机位连续几天」的样本是否真的同分布（光照渐变、个体移动、蜕皮位置不同都可能打破）；以及每台设备一份原型/模型的存储与隐私边界。因此在有真机数据前，只把这条方向记在 `docs/handoff.md` 的「待确认」，不写进正式规格。
